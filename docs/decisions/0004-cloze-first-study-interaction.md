# Decision 0004: 문맥 빈칸 중심의 단어 문제풀이

상태: accepted  
날짜: 2026-09-09

## 결정

오늘의 학습은 뜻만 보고 답을 쓰는 방식이 아니라, 한국어 뜻과 자연스러운 영어 예문을 함께 보여주고 목표 표현을 빈칸으로 가린 뒤 직접 입력하는 흐름을 기본으로 사용한다.

한 문제의 기본 순서는 다음과 같다.

1. 영어 예문에서 학습 대상 표현을 가린다.
2. 한국어 뜻을 단서로 제공한다.
3. 사용자가 문장 안의 빈칸 밑줄에 직접 키보드로 답을 입력하고 Enter 또는 정답 확인을 누른다. 밑줄 너비는 목표 표현의 글자 수를 기준으로 잡는다.
4. 서버가 정답을 판정하고 완성된 문장과 함께 `정답 · 뜻`을 한 줄의 핵심 정보로 보여준다. 오답일 때만 `내 답`과 다음 복습 시간을 추가한다.
5. 틀린 응답은 짧은 복습 주기로 다시 큐에 들어간다.

## 이유

문장 속에서 단어를 꺼내 쓰게 하면 단순 암기보다 실제 사용 맥락을 함께 회상할 수 있다. 직접 입력을 기본으로 두면 객관식으로 우연히 맞히는 일을 줄이고, 기존 복습 기록의 typed 정답률도 의미 있게 유지된다.

힌트, 객관식, 정답 보기 후 자기평가는 주 풀이를 방해하지 않도록 보조 영역으로 접어 둔다. 보조 수단을 사용한 응답은 기존 review mode와 hint 플래그로 기록해 통계에서 직접 입력 정답과 구분한다.

## 데이터·안전 경계

- 빈칸 가리기는 화면에서만 수행하며 정답 판정은 계속 서버의 `submit_review` RPC가 담당한다.
- 클라이언트가 보낸 정답이나 단어 정보는 신뢰하지 않는다.
- 예문에 학습 대상 표현이 없거나 예문이 비어 있으면 뜻 중심의 안전한 fallback을 사용한다.
- 단어의 첫 등장, 오답, 힌트 사용, 복습 간격은 기존 사용자별 RLS와 RPC 정책을 그대로 따른다.

## 추후 확장

브라우저 음성 인식은 별도 review mode와 권한 안내가 필요하므로, 현재는 키보드 모드를 먼저 안정화한다. 음성 입력을 추가할 때는 음성 권한 상태, 지원 브라우저, transcript 저장 여부를 함께 설계한다.
