# WordLoop 홈 대시보드 실험

2026-09-14 · 구현 제안이 아닌 독립 목업. 실제 데이터·인증·저장·복습 알고리즘 연결 없음.

## 관찰 근거와 범위

`AGENTS.md`, `docs/AGENTS.md`, `src/AGENTS.md`, `DESIGN.md`와 아래 현재 작업 트리 코드를 읽었다. 기존 미커밋 변경을 포함한 코드 기준이며, 로그인한 실제 화면이나 서비스 데이터를 관찰한 결과는 아니다.

| 현재 화면 / 근거 | 유지할 점 | 실험에서 바꿀 점 |
| --- | --- | --- |
| 공개 홈 `src/app/page.tsx` | 베이지·검정·테라코타, 문장 속 회상 | 로그인 전 마케팅 구성은 로그인 후 홈으로 가져오지 않는다. |

숙련도의 근거는 `docs/decisions/0007-word-mastery-and-example-meaning.md`다. 이는 응답 방식에 따라 증감하는 누적 점수이며 기억 확률·정답률·사용자 전체 수준이 아니다. 복습 시점은 별도 상태가 결정한다. 낮은 점수를 이유로 예정 시간을 임의 변경하지 않는다.

## Visual thesis

따뜻한 종이색 바탕에 검은 활자와 짙은 주황 시작 버튼을 놓고, 한 장의 학습 목록처럼 읽히는 조용한 홈을 만든다.

기존 브랜드를 유지하되 제목은 모바일 30px, 본문 16px, 보조 글 14px로 압축한다. 시스템 산세리프 한 계열과 400/600/700 굵기, 4/8/12/16/24/32/48px 간격을 사용한다. 바탕 `#f4f1ea`, 본문 `#211f1b`, 보조 `#625e57`, CTA `#b9472f`를 사용한다. 숙련도는 숫자·상태 문구를 기본으로 두고, 기존 4단계(낮음·진행 중·자리 잡는 중·안정적)의 색상으로 빠른 스캔을 보조한다. 색상만으로 상태를 판정하지 않으며 CTA 주황과 숙련도 색은 구분한다.

`frontend-skill`의 앱용 절제·행 목록·실용 문구를 적용했다. 브랜드를 가장 크게 만들기, 이미지 중심 히어로, 입장 연출은 이 학습 작업공간에 적용하지 않는다. 첫 문제를 시작하는 행동이 시각적 중심이다.

## Content plan

1. **방향 확인:** 64px 높이의 한 줄 WordLoop / 오늘 / 단어장 / 기록. 홈에는 ‘오늘로 돌아가기’를 추가하지 않는다.
2. **시작:** 날짜, ‘오늘의 학습’, ‘오늘 복습 대기 8개’, 새 단어 4개와 총 12개 구성, ‘오늘의 단어 시작하기’. 대기 수는 학습 가능한 기한 도래 단어이며 전체 소장 단어 수가 아니다.
3. **오늘의 상태:** 목표 20회 중 완료 8회, 단어 수와 응답 횟수가 다른 단위임을 짧게 설명한다. 이 값은 홈에서 한 번만 표시한다.
4. **주의할 단어:** 최근 틀린 단어 세 개. 단어·뜻·숙련도/상태·오답 날짜·복습 시점·예문 확인을 한 행에 연결한다. 이 세 개는 오늘 복습 8개의 부분집합이며 추가 할당량이 아니다.
5. **이차 경로:** 단어장과 기록은 상단 메뉴로 접근한다. CTA를 페이지 말미에 복제하지 않는다. 열람용 대화상자는 목업의 가상 단어/최근 기록만 제공한다.

데스크톱은 시작과 오늘 진행을 2:1로 배치하고 아래에 넓은 단어 목록을 둔다. 모바일은 같은 DOM 순서로 쌓는다. 설명을 접어야만 수치 의미가 드러나는 구조를 피한다.

## Interaction thesis

- 시작은 소개 화면 없이 빈칸 문제 대화상자를 연다. 입력에 포커스하고 Enter로 확인한다. 정답 확인 → 다음 단어 → 세션 완료까지 가상 12문제를 진행할 수 있다.
- ‘예문 보기’는 선택한 단어의 예문·숙련도·다음 복습을 열고 닫으면 원래 버튼으로 돌아온다. 열람은 학습 완료에 포함하지 않는다.
- hover 배경과 140ms 대화상자 등장만 허용한다. 반복·스크롤 연출은 없다. reduced-motion에서는 이동과 전환을 없앤다. 기본 dialog의 Escape, 포커스 가두기와 명시적 닫기 버튼을 사용한다.

목업은 메모리에만 상태를 유지하며 새로고침하면 초기화된다. 제출한 응답은 완료 수와 세션 진행에만 반영한다. 숙련도 증감과 복습 재예약은 흉내 내지 않는다. 끝까지 풀면 목표 20회 달성을 보여주고, 주 행동은 ‘오늘의 단어 다시 보기’로 바뀐다. 중간에 닫으면 ‘오늘의 단어 이어하기’로 재개한다. 재학습도 새로운 응답이므로 완료 수는 목표를 넘어갈 수 있다.

## 새 대시보드 규칙

1. 홈의 질문은 ‘지금 무엇을 얼마나 하면 되나?’다. 분석보다 회상 시작을 우선한다.
2. 최초 상태의 유일한 채움 CTA는 정확히 ‘오늘의 단어 시작하기’다. 방향 확인 → 양 확인 → 시작 순서를 첫 화면 안에 둔다.
3. 단어 수, 응답 횟수, 숙련도 점수를 구분한다. ‘8 완료’처럼 단위 없는 수치를 쓰지 않는다. 숙련도는 `/100`으로 표시하고 `%`로 바꾸지 않는다.
4. 복습 대기와 오답은 다른 집합이다. 오답 여부와 다음 복습 시점을 함께 보여주고, 이 실험의 오답 세 개가 대기 목록에 포함됨을 밝힌다.
5. 숙련도는 단어별로만 표시한다. 기존 30/60/85 경계의 상태 문구를 유지한다. 평가 전은 0점과 구분하고, 100점도 영구 습득으로 표현하지 않는다.
6. 목록은 최근 오답 시각 순, 같은 단어는 최근 기록 하나만 표시한다. 홈은 최대 세 행만 노출한다. 모든 단어를 점수순으로 탐색하게 만들지 않는다.
7. 정보는 결정을 바꾸는 곳에 둔다. 수준·신뢰도·정답률·연속 학습일은 홈 시작의 선행 조건이 아니다. 기존 기록의 유용성 자체를 부정하지 않는다.
8. 같은 홈에서 동일 수치를 별도 지표로 반복하지 않는다. 단어 행의 점수와 그 점수를 나타내는 막대는 읽기 보조이므로 중복 KPI로 보지 않는다.
9. 320px 이상에서 한 열로 읽히고 가로 스크롤하지 않는다. 모바일 여백 16px, 제어 최소 44px, CTA 52px. 큰 숫자보다 시작 버튼과 문맥의 동시 노출을 우선한다.
10. 색상 없이도 상태를 알 수 있게 상태 문구와 점수를 함께 표시하고, 색상은 기존 숙련도 4단계의 의미 보조로만 사용한다. 포커스는 별도 청색 윤곽선을 유지하고, CTA 주황을 숙련도나 오답 경고에 재사용하지 않는다.
11. 대기 0개면 ‘오늘 복습 대기 0개’와 실제 확보 가능한 새 단어 수를 구분한다. 처음 방문은 ‘평가 전’, 오답 없음은 짧은 빈 상태를 사용한다. 오류는 0으로 위장하지 말고 재시도를 제공한다. 이 변형들은 문서 규칙이며 현재 목업 초기 상태에 전부 구현된 것은 아니다.

## 비교 평가표와 검증 가설

현행 평가는 코드 관찰, 목업 평가는 설계 가설이다. 시간·성공률 개선은 아직 측정하지 않았다.

| 기준 | 현재 화면 | 실험 목업 | 측정 방법 / 예상 트레이드오프 |
| --- | --- | --- | --- |
| 사용자 여정 | 홈 시작 → 학습 소개 → 시작 → 문제 | 홈 시작 → 첫 문제 | 첫 입력 가능 상태까지 명시적 클릭 2→1. 준비 설명이 줄어 초보자의 이해가 낮아질 수 있다. |
| 인지 부담 | 시작·진행·수준/신뢰도·3개 지표·최근 추가 단어 | 시작·오늘 진행·최근 오답 | ‘무엇을 할지/점수 의미’를 5초 노출 후 질문. 정답률 80% 이상 목표. 오답 강조가 부담을 줄 수도 있다. |
| 첫 행동까지 시간 | 실제 시간 미측정; 중간 시작 화면 존재 | 초기 CTA를 첫 화면에 배치 | 동일 가상 상태에서 첫 CTA 및 첫 입력까지 각각 측정. 첫 입력 중앙값 25% 감소가 가설이며 결과가 아니다. |
| 정보 중복 | 오늘 완료 수가 진행과 metrics에 반복 | 홈 완료 수 한 곳, 오답 부분집합 명시 | 홈의 독립 중복 KPI 1→0. 기록에서 숫자를 재확인하는 것은 허용. |
| 모바일 공간 | 두 줄 셸·페이지 제목·큰 대기 수 후 CTA; 진행은 아래 | 한 줄 셸, 압축된 시작과 진행, 아래 단어 행 | 360×640에서 CTA와 오늘 완료 상태가 스크롤 없이 보이는지 확인. 320px 및 200% 확대에서는 정보 보존과 세로 스크롤을 우선. |

가설 검증은 동일 가상 데이터의 기존 화면과 목업을 순서 교차로 제시하여 5–8명의 사용성 세션에서 한다. ‘최근 틀린 단어가 복습 8개에 더해지는가?’, ‘숙련도 60은 정답 확률인가?’를 물어 의미 혼동도 함께 기록한다. 예문을 미리 본 사용자의 회상 수행은 별도 관찰한다. 소규모 결과를 통계적 효과로 주장하지 않는다.

가장 큰 비용은 홈에서 성취감과 장기 추세가 줄어드는 것이다. 시작 시간이 줄어도 재방문 의욕이 떨어지면 연속 학습일을 다시 홈에 넣기 전에 기록 진입과 완료 후 피드백을 검토한다. 한 번 클릭으로 문제를 여는 설계의 실제 도입에는 서버 세션 준비·오류·중복 시작 처리와 별도 검증이 필요하다.

## 산출물과 확인 범위

`docs/mockups/wordloop-dashboard-experiment.html`을 브라우저에서 직접 연다. 외부 폰트·이미지·스크립트·프레임워크·저장소 API를 호출하지 않는다. 가상 단어와 날짜는 파일에 고정되어 있다. 제품 UI에는 설계 비평 문구를 넣지 않고 가상 데이터라는 사실은 이 문서와 HTML 주석에 기록했다.

새 파일은 이 문서와 HTML 두 개뿐이다. 앱 소스·테스트·package 설정·기존 문서는 변경하지 않는다. 실제 인증·DB·학습 채점·예약·릴리스 검증은 이 실험의 확인 범위가 아니다.

실행 확인: 로컬 파일을 headless Chromium에서 열어 320/360/390/768/1440px 너비에서 가로 넘침이 없음을 확인했다. 360×640에서 CTA 하단은 365px, 오늘 상태 설명 하단은 504px로 모두 첫 화면에 들어왔다. 가상 12문제 완료 후 응답 8→20회, 오답 피드백, 중단 후 재개, 예문/단어장/기록 열기, Escape와 원래 버튼으로 포커스 복귀를 확인했다. reduced-motion에서 대화상자 animation은 none이며 외부 요청과 JavaScript 실행 오류는 없었다. 별도 테스트 파일·스크린샷 파일은 만들지 않았다. 실제 기기·스크린리더·사용자 시간 측정과 시각적 비교 검증은 미실시다.
